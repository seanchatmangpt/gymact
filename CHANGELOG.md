# Changelog

## 26.8.8 - 2026-08-08

### Added

- OCEL 2.0 process-mining export off any episode's real receipt trail: `GymAct.episode_receipts()` and `GymAct.episode_ocel_log()`, backed by a new receipt-accumulation chokepoint (`_emit`) that every existing lifecycle call now routes through.
- `probe_repo` FastMCP tool: a read-only repository prober (README/pyproject/setup.py plus a top-level listing, truncated) with no shell/exec access -- actual command execution stays behind `actuate()`/authority, unaffected by this addition.
- `GenericDiscoveredProvider` (`gymact.gyms.discovered`): a generic `EnvironmentProvider` that runs an LLM-proposed, bounded subprocess recipe (`command`/`cwd`/`timeout_seconds`/`success_markers`) against an arbitrary checked-out repo, rather than a hand-written adapter per benchmark subject.
- `scripts/discover_and_actuate.py`: an end-to-end probe -> propose -> actuate -> OCEL driver exercising the above.
- `scripts/ocel_standing.py`: a strict standing-derivation script that computes actuation standing purely from on-disk OCEL logs (schema validation + `ConformanceChecker` replay + an explicit `solved=True` marker check on `act` receipts). Currently scoped to the `GenericDiscoveredProvider` convention specifically -- it does not yet recognize other providers' own success signals (e.g. `TerraformPlanProvider`'s `verify()` boolean), so a passing provider-level test suite is not automatically the same claim as a `GYMACT_ACTUATED` corpus standing for those providers yet.
- Real cross-validation: an episode's exported OCEL log is independently re-validated via a real `cargo run --bin wpm -- receipt verify-ocel2` subprocess against `~/wasm4pm` (`tests/test_ggen_legacy_gym.py::test_ocel_export_is_independently_validated_by_wasm4pm`), skipping cleanly via `require_standing` when no local wasm4pm checkout is present.
- `KubernetesReconciliationProvider` (`gymact.gyms.kubernetes_reconciliation`): a real `kubectl`-subprocess-backed provider whose `materialize()` applies a real manifest to a real local `kind` cluster and whose `verify()` polls real cluster-observed pod phase rather than trusting `kubectl apply`'s exit code.
- `McpClientSessionProvider` (`gymact.gyms.mcp_client_session`): a real `fastmcp.Client` session against a real subject MCP server (client-of-a-subject, distinct from GymAct's own existing MCP server-side surface).
- `TerraformPlanProvider` (`gymact.gyms.terraform_plan`): a real `terraform`/`tofu` `init -backend=false` + `plan` provider with exactly one DO capability (`plan`) and structurally no `apply`/`destroy` capability.
- `TerraformDockerApplyProvider` (`gymact.gyms.terraform_docker_apply`): a real `apply`/`destroy`-capable Terraform provider, safely scoped to a hand-authored, checked-in config targeting only colima's local Docker daemon (`kreuzwerker/docker` provider) -- never a cloud provider.
- `VendorBenchmarkProvider` (`gymact.gyms.vendor_benchmarks`): exact-pinned-revision admission and safe native-subprocess execution against any of the 52 vendored ForwardBench benchmark checkouts, refusing on revision mismatch or command-escape rather than silently degrading.
- `InspectEvalsProvider` (`gymact.gyms.inspect_evals`): a real `inspect_ai` `eval_async()` gym.
- `tests/test_ocel_standing.py`: per-gym standing asserted directly against real OCEL 2.0 state (real schema validation, real `ConformanceChecker` replay, real `solved=True` evidence read off a real `act` event's own attributes) -- never a hardcoded expected value or a summarizing script's packaged verdict. Codified as policy in `.claude/rules/ocel-standing.md`: a gym's pytest suite passing is a claim about `request accepted`, not `objective verified`.
- `docs/integrations/consumer-setup.md` and `ggen/consumer-bridge-pack-template/`: the integration guide and a copy-and-customize ggen pack for an external system (e.g. `autofde-lab`) registering its own `EnvironmentProvider` and declaring its own capability ontology, verified end-to-end with a real `ggen sync run` against a real `gymact export-profile` export (both the happy-path generation and the SHACL-gate refusal path).
- `MulticloudProvider`/`MulticloudEnvironment` (`gymact.gyms.multicloud`): a **SIMULATED** multicloud IAM/storage/compute gym -- 20 capabilities across AWS/Azure/GCP (7/6/7), in-memory state only, no real cloud SDK calls and no credentials of any kind. Ontology (`ggen/multicloud-gym-pack/ontology.ttl`) grounds every capability in `sosa:Procedure` (base typing) and `dct:title`/`dct:type` (SHACL-required), with `odrl:Permission` on the 3 policy-attach/role-assign operations, `org:Role` on `aws.iam.create_role`, `dcat:Distribution` on the 3 bucket/account-creation operations, `prov:Entity`/`prov:Activity` on the 3 compute-provisioning operations, a `skos:ConceptScheme` taxonomy classifying all 20 capabilities by provider and service-domain, `time:Interval` authority-window instances on the 3 real policy-assignment operations, and `org:OrganizationalUnit` instances for account/subscription/project containment -- zero new `rdfs:Class`/`owl:*Property` declared throughout. `qudt`/GeoSPARQL/DPV/SPDX/FOAF/`dqv` were each evaluated against the gym's real capabilities and rejected with reasons documented in the ontology file's own header (no quantities, no geometry, no PII, no packages, no named individuals, no computed quality metric anywhere in the real handler code). `tests/test_multicloud.py`: 14 tests pass, including a real rdflib ontology-vs-`CAPABILITY_REGISTRY` parity check; zero matches on the required mock-usage grep. `ggen/multicloud-gym-pack/` (`pack.toml` + templates, adapted from `ggen/consumer-bridge-pack-template/`) manufactures a Rust operation catalog, MCP tool schema, reference doc, and cross-check proof test from this ontology -- verified with a real `ggen sync run` (ggen 26.8.6): all 4 files written, real content, 20 operations correctly classified Read/Do.
- `.claude/rules/ontology.md`: added GeoSPARQL/DPV/SPDX/FOAF rows to the vocabulary table plus a "gap documentation" rule -- a rejected candidate vocabulary must be named in the consuming file's own header (what was searched, why it didn't fit), not silently omitted, matching what `ontology.ttl` files already did in practice.
- `tests/test_semantic_capability.py::test_ggen_pack_ontology_declares_zero_custom_tbox`: closes a real coverage gap found by a hardening audit -- neither `ggen/gymact-bridge-pack/ontology.ttl` nor `ggen/multicloud-gym-pack/ontology.ttl` was previously run through `ProfileAuthority`'s zero-custom-TBox admission check (only the packaged `src/gymact/ontology/profile.ttl` was), so a custom class/property smuggled into either pack ontology would previously have passed silently.
- `Receipt.combinatorial_binding_is_atomic` (`src/gymact/models.py`) now also refuses `PARENT_RECEIPT_SELF_REFERENCE` (a receipt citing its own `receipt_id` as a parent) and `PARENT_RECEIPT_IDS_DUPLICATE` -- another real gap found by the same hardening audit; no production call site (`crown_runtime.py`, `cut.py`) currently constructs either invalid shape, so this closes the gap with zero behavior change to existing flows.
- `.claude/rules/actuation-authority.md`: documents the closed authority-default gap below plus what was deliberately reverted, per `ocel-standing.md`'s "name the real gap" discipline.
- `MemoryReceiptLedger`/`SQLiteReceiptLedger` (`src/gymact/evidence.py`, `src/gymact/sqlite_ledger.py`) now refuse `IDEMPOTENCY_KEY_REUSE_WITH_DIFFERENT_INTENT` when a new receipt reuses an `idempotency_key` already bound to a different `episode_id`/`capability_ref` -- closes a real gap where `append()` previously deduped only by `receipt_id` (a random UUID), so two receipts sharing an `idempotency_key` with a genuinely different intent both appended without conflict. Comparator field set was narrowed twice during implementation after real testing caught it incorrectly refusing this codebase's own legitimate internal receipt-refinement chains (`crown_runtime.py`'s ACT->VERIFY receipt pair, which legitimately shares one `idempotency_key` across a different `operation`; `execute_admitted`'s "bound" receipt, which legitimately re-derives `subject_ref` in a different vocabulary than the kernel-level receipt it refines; `cut.py`'s `CombinatorialBRCEBroker`, which legitimately re-receipts with refined lineage/combinatorial-binding fields) -- final field set is `episode_id`/`capability_ref` only, the two fields verified stable across every real internal flow.

### Fixed

- 4 real, independently-reproducing test/source gaps (all fail standalone, not order-dependent): stale `basis_refs`/`possibility_exploration_digest` fixtures in `test_combinatorial_receipt.py`/`test_combinatorial_replay.py`; a real tuple-vs-list JSON round-trip bug in `PossibilityObject.attributes` breaking `test_dcm_decision_court.py`'s lossless-RDF-projection check (fixed with a `field_validator` canonicalizing `attributes` at construction, in `src/gymact/combinatorial.py`); and the `cli.py` `demo` command's authority-bypass bug above.
- 2 GC-timing-dependent flaky test failures (passed standalone, failed only in full-suite runs): an `sqlite3.Connection` resource leak in `src/gymact/local_providers.py` (`with sqlite3.connect(...) as connection:` only commits/rolls back, never closes -- fixed with `contextlib.closing` at all 4 call sites), and a documented upstream `inspect_ai` 0.3.252 internal-stream cleanup gap bleeding a `PytestUnraisableExceptionWarning` into an unrelated later test (`test_ocel.py`) purely from suite ordering -- extended the same scoped `filterwarnings` suppression `test_inspect_evals.py` already used for its own tests.
- **Authority default bypass in 8 real-side-effect providers**: `config.get("requires_authority", False)` flipped to `True` in `kubernetes_reconciliation.py`, `terraform_docker_apply.py`, `terraform_plan.py`, `cube_container_counter.py`, `gymnasium_env.py`, `mcp_client_session.py`, `inspect_evals.py`, `cube_counter.py` -- the exact bug class fixed in `cli.py`'s `demo` command, but present by default in every DO capability these 8 providers expose. Every test in the corresponding 8 test files that previously relied on the old default was individually updated (`GymAct(authority_resolver=AllowListAuthorityResolver({AUTHORITY}))` + explicit `authority_ref` on every real `act`/`restore`/`teardown` call) -- confirmed with real integration runs against a real local `kind` cluster, real Docker daemon (colima), and real `terraform`/`inspect_ai`/`gymnasium` invocations, not mocked. See `.claude/rules/actuation-authority.md` for what was deliberately tried and reverted (`materialization_requires_authority`, `discovered.py`, `browsergym.py`, `MemoryProvider`) after real testing showed a broader blast radius than the demonstrated bug.
- Full suite confirmed deterministic across two consecutive runs after all of the above: only the 3 intentionally-red `test_ocel_standing.py` cases (`qqr`, `r2e-gym`, `terraform-plan-terragoat-alicloud`) remain, per `.claude/rules/ocel-standing.md`'s own policy that those name real, unresolved actuation gaps and must not be silenced.

### Known gaps (named, not fixed this release -- see `.claude/rules/actuation-authority.md`)

- `EnvironmentProvider.materialization_requires_authority` (the separate knob gating `materialize()` itself) and `MemoryProvider`'s `requires_authority` default remain `False` -- both were flipped and reverted after real testing showed a blast radius wider than the demonstrated bug (`materialize()` itself breaking for a plain `GymAct()`; ~27 core-kernel test failures unrelated to the original audit, respectively).

## 26.8.7 - 2026-08-07

### Added

- Public-ontology GymAct application profile using PROF, PROV-O, P-PLAN, SOSA/SSN, WoT TD, ODRL, SHACL, EARL, DQV, QUDT, DCAT, SKOS, OWL-Time, and Dublin Core Terms.
- Mechanical zero-custom-TBox admission check plus real pySHACL validation.
- `sosa:Procedure` capability projection with SHACL-enforced title and READ/DO consequence classification.
- Pydantic v2 canonical runtime models separating semantic capability IRI from provider-local binding.
- Environment/EnvironmentProvider execution boundary and deterministic reference MemoryProvider.
- Receipted, idempotent environment materialization with optional external authority admission.
- Fail-closed external AuthorityResolver for consequential actuation, restore, and teardown.
- Per-episode concurrency serialization, exact idempotent replay, and conflicting-key refusal.
- Bounded provider failure receipts with error digests rather than arbitrary provider text.
- Independent observation and verification; benchmark scoring remains a distinct layer.
- Native Python surfaces through FastAPI/OpenAPI, FastMCP, Typer, and FastStream.
- Profile export for ggen/Rust/WIT/WASM or other independent compilers.
- Python 3.11/3.12/3.13 CI, strict docs, clean wheel/sdist installation, and production container admission gates.

### Architectural rule

Python composes mature Python libraries directly. Rust/WIT/WASM projections are manufactured separately from the same admitted semantic graph. Provider bindings are implementation detail; public semantic capability identity is the interoperability boundary.

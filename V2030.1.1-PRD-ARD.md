# gymact v2030.1.1 — PRD / ARD

**Repository:** `seanchatmangpt/gymact`  
**Ecosystem role:** actuation-model / executable world and gym framework  
**Depends on:** `ggen`, `open-ontologies`  
**Release:** Chatman Ecosystem v2030.1.1  
**Standing conferred:** `UNKNOWN`.

## Product requirement

`gymact` SHALL make environments executable as bounded semantic worlds so planners can observe, simulate, validate, and compare actions before authorized production execution. By v2030.1.1 it is the common substrate for cloud gyms, marketplace gyms, enterprise-system gyms, security gyms, and other exact-enough world models used by AutoFDE and FDEGym.

The product objective is **GPS rather than maps**: represent environment objects, relationships, admissible actions, transition semantics, costs, refusals, and evidence in machine-operable form.

## Required capabilities

1. Consume canonical/public ontology semantics from `open-ontologies` and manufactured action/environment projections from `ggen`.
2. Define `World`, `Object`, `ObservationProjection`, `ActionProjection`, `Action`, `Transition`, `Role`, `Policy`, `InformationPartition`, `Authority`, `Episode`, `Reward/Objective`, `Cost`, `Receipt`, and `Falsifier` as explicit concepts.
3. Support deterministic reset/step/observe/validate/cost/diff/receipt interfaces where the modeled environment permits.
4. Model typed provider/API refusals, quotas, regions, identity, dependencies, lifecycle transitions, failure modes, and pricing.
5. Distinguish simulation, emulation, live observation, live execution, and independent verification.
6. Support multi-agent/planner episodes without conflating planner, policy, role, and agent.
7. Permit exact live-provider validation against available APIs/docs/fixtures while preserving the boundary between modeled and observed behavior.
8. Emit receipts binding world version, initial state, action, authority class, transition, result, and replay identity.

## Architecture requirements

```text
public ontology + provider contracts + observed APIs/docs
        -> admitted world/action graph
        -> generated gym projection
        -> reset/observe/step/validate/cost
        -> transition evidence
        -> compare with live provider where authorized
        -> fidelity receipt
```

Gym actions SHALL NOT inherit production authority merely because they have the same shape as provider actions. A simulated `step()` is CONSTRUCT/evaluation. Live DO requires a separately admitted authority path through BRCE or the owning runtime boundary.

## DfCM requirement

The gym SHALL preserve combinatorial alternatives—providers, regions, services, policies, topologies, and action sequences—until constraints lawfully eliminate them. One unsupported provider edge is topology, not global failure.

## Acceptance for v2030.1.1

- common world/action interfaces support materially different environment families;
- deterministic gym episodes replay under pinned world/config/toolchain identities;
- negative fixtures prove invalid transitions and authority violations refuse;
- representative cloud actions are validated against live public API behavior where credentials/authority are available;
- fidelity reports identify modeled, observed, unsupported, and unknown semantics separately;
- planner policies can be benchmarked without receiving production authority;
- receipts distinguish simulated consequence from real external consequence.

## Falsifiers

The architecture is falsified if simulated success is reported as live-provider success; if provider-specific objects force provider semantics into the canonical world model; if a planner can call production APIs through an unbounded gym action; or if model fidelity cannot be measured against observed external behavior.

## Ecosystem contract

`gymact` makes worlds and actions executable for reasoning and validation. `autofde-lab` explores policies over those worlds; `autofde` exploits admitted plans under BRCE; `fdegym` composes Fortune 5 evaluation. World modeling is not ambient production authority.
